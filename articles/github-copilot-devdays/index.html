Take Stock of Model Context Protocol with .NET - Peter Bull

Large language models can be powerful, they can generate text or code, but they can't do anything in the real world, without a bridge between models and reality. Tools perform actions on your behalf to invoke functions with named operations along with defined inputs. Resources deliver structured data to context of large language models with Markdown or other formats, from a named data source with description and schema defining the structure. Prompts control output from large language models to provide templates with reusable instructions that can shape a large language model's approach to tasks.

Model Context Protocol, or MCP, is the standard to bridge AI apps from large language models to reality with external systems, it was created in 2024 by Anthropic with many MCP servers being implemented and used daily by developers such as for Jira, Azure DevOps and more. Servers implement Model Context Protocol to expose actionable tools, define data resources and provide reusable prompt templates to clients. These clients such as GitHub Copilot can leverage Model Context Protocol servers to take advantage of their functionality. To find out more about Model Context Protocol or MCP then visit modelcontextprotocol.io.

Model Context Protocol is an evolving standard, with support for Skills coming soon, these provide reusable capabilities to enable AI clients to perform specialised tasks currently supported today in many clients with local SKILLS.md Markdown files, which define when they should be used and contain instructions or workflows that can combine actions from tools or knowledge from resources and define expected inputs or outputs. Servers will be able to add to the capability of local SKILLS.md files with Skills over Model Context Protocol with updates to libraries to enable servers to support this along with clients will be coming soon.

Model Context Protocol extends the ability of large language models with actions that can use natural language requests such as finding products or updating stock. You can build for Model Context Protocol in a variety of languages and frameworks, such as .NET which is Microsoft's open-source cross-platform runtime that supports desktop, mobile and web for modern applications and C# the programming language used in .NET where there is an official C# MCP SDK to expose tools, resources and data. You can connect a client supporting Model Context Protocol such as GitHub Copilot which can use the appropriate tools and resources to present results. You can leverage Model Context Protocol in Visual Studio 2026 on Windows which supports the broadest range of features for tools, resources and reusable prompts or take advantage of most features in Visual Studio Code and GitHub Copilot app. You can find out more about .NET at dot.net, GitHub Copilot at gh.io/copilot or Visual Studio 2026 at visualstudio.com.

Model Context Protocol can be used through a variety of developer tools such as Visual Studio 2026 which can use GitHub Copilot as the client to connect natural language requests to a server implemented in .NET and the C# MCP SDK, available as a seperate template in .NET 10 but built in with the upcoming .NET 11, using MCP over HTTP. Server can provide a variety of tools to enable a client to find or create products or update stock, sales and get sales history that uses a database for storing operations along with code providing deterministic validation of actions so invalid actions such as creating negative stock or cost situations cannot be performed. Resources can provide clients with a sample catalogue, stock examples and expected results stored in embedded Markdown, which can also be used to for prompts which provide reusable instructions to guide how client can approach or perform tasks. You can check out a demo using Model Context Protocol with .NET using the C# MCP SDK at github.com/rogueplanetoid/takestockofmcpwithdotnet.
